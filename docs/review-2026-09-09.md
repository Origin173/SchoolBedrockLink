Actual Chromium submission remained on the home page and emitted a `form-action 'self'` console violation. Running the fixture without `--baseline` allowed navigation to the provider. Same-origin probes and curl 302 responses alone are not sufficient evidence.

The Java `browserFixture` Gradle task then exercised production handlers at port 18793 under `/auth/`, with a simulated provider at port 18794: home → start → external authorize → login → callback → role selection → confirm displayed binding success in Chromium. Provider and Floodgate are test doubles, not the deployed services. Firefox execution was attempted but its browser executable was unavailable.
